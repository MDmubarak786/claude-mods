# Maintaining this repository

For people with write access. Contributors want [CONTRIBUTING.md](../CONTRIBUTING.md).

## Repository settings

The settings below live in [`scripts/apply-github-settings.sh`](../scripts/apply-github-settings.sh), which applies all of them idempotently. Change them there and rerun it, rather than in the GitHub UI, so the file stays the record.

```bash
scripts/apply-github-settings.sh
```

### Branch protection on `main`

| Rule | Setting | Why |
| :-- | :-- | :-- |
| Pull request required | 1 approving review, from a code owner | Every mod runs with users' permissions; someone other than the author reads it. |
| Stale reviews dismissed | On | A review covers the code it saw, not later pushes. |
| Required status check | `validate`, branch up to date with `main` | Strict validation, every mod's tests, and the generated-file checks on the exact commit that merges. |
| Conversations resolved | Required | Review questions get answered, not merged past. |
| Linear history | Required | One squash commit per pull request keeps `git log` readable and each commit valid. |
| Force pushes and deletion | Blocked | `main` is the marketplace users install from. |
| Admins | Not enforced | This is a single-maintainer project. The owner's own pull requests still need a green `validate`, but can be merged without a second reviewer using the admin bypass. When a second maintainer joins, turn `enforce_admins` on. |

### Merging

Squash merge is the only method allowed, titled from the pull request title, and the branch is deleted after merge. To merge your own pull request once `validate` is green:

```bash
gh pr merge <number> --squash --admin --delete-branch
```

Never use `--admin` to merge past a red `validate`.

### Labels

| Label | Applied by | Meaning |
| :-- | :-- | :-- |
| `needs-triage` | Every issue form | Not looked at yet. Remove it once labeled and answered. |
| `bug`, `enhancement`, `idea`, `documentation` | The issue form used | What the issue is. |
| `security` | A maintainer | Reaches further than it should. Prefer private advisories. |
| `mod`, `documentation`, `ci` | The labeler workflow, by changed paths | What a pull request touches. |
| `new-mod` | The labeler workflow, when a pull request adds a `plugin.json` | A new mod to review against the full checklist. |
| `dependencies` | Dependabot | Action version bumps. |
| `breaking` | A maintainer | Changes what an installed mod does in a way users will notice. Call it out in the PR title. |
| `good first issue`, `help wanted` | A maintainer | Invitations. |

## Triage

1. Read new issues with the `needs-triage` label at least weekly.
2. For a bug, reproduce it with `scripts/try.sh <name>`. Ask for the missing field rather than guessing.
3. For an idea, check the three things the roadmap requires: evidence, the nearest existing mod, and how it would work. If it passes, add it to [docs/roadmap.md](roadmap.md) under **Wanted** and link the issue.
4. Remove `needs-triage`.

## Reviewing a pull request

Use the [review checklist](review-checklist.md). The `validate` check covers what can be automated; the checklist is for what can't, chiefly whether every `$` call is necessary for the mod's stated purpose and explained in its README.

## Releasing

There's no separate release step. A mod is released when a pull request that bumps its `version` merges to `main`: users with auto-update get it at their next session, and others get it with `/plugin marketplace update modhub`. That's why CI refuses a change to a mod without a version bump.

## Security reports

Private vulnerability reporting is on. A report arrives as a draft advisory. Acknowledge it within three days, fix it on a private branch from the advisory, publish the advisory with the fix, and bump the mod's version so installs update. Credit the reporter if they want it.

## Retiring a mod

Remove its entry from `.claude-plugin/marketplace.json` and add `"<name>": null` to a top-level `renames` map, so installed users see "Removed from the marketplace" instead of an error. To uninstall it from users' machines too, set `"forceRemoveDeletedPlugins": true`. Keep the `renames` entry forever.
